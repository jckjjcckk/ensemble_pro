# Folio: interaction and animation audit for the iPad

Scope: tappability, gestures, feedback, transitions, scrolling, iPad layout and perceived responsiveness in `web/src`. Not content, copy, colour, shape or type.

How it was produced (2026-10-28): every file in `web/src` read; the app run in the desktop app's built-in browser (Chromium) at 1024×768 and 820×1180 against the local Supabase stack, using the `violin2@muse.test` session the browser profile already held (Vite started on :5174 with the local env in the shell; no file under `web/` or `api/` touched; the hosted project was not signed into). Drags used the real mouse; taps, swipes and holds on the score stage used synthesised touch `PointerEvent`s. Timings are from an Apple-silicon Mac; expect OSMD work to be 2–5× slower on an iPad. Not testable here: Safari's own touch physics (momentum, rubber band), the on-screen keyboard, link callouts, standalone (home-screen) mode, Pencil. Those rows say "from code".

Severity: **blocks** = blocks the premium feel · **noticeable** · **polish**.

## C. Motion

- Colour-only transitions of 120–180 ms on buttons, segs, nav, pins (`styles.css:250, 272, 298, 309, 407, 440, 561, 577, 591, 657, 834`).

## F. Shortlist (highest feel-per-hour first)

1. **Pressed states and `touch-action: manipulation` everywhere.** One CSS pass: `:active` darken + `transform: scale(0.97)` (120 ms out, 40 ms in) on `.dbtn .tog .pd-play .area .seg button .cover .pin .btn .turn .m-body`, `touch-action: manipulation` on `.fo button, .fo a`, `-webkit-touch-callout: none` and `user-select: none` on controls, drop the `:hover`-only lift on covers. Effort 1–2 h. All screens. No PinList mechanic (pure CSS), but it is the precondition for everything else reading as responsive.
2. **Stop the stage re-engraving when chrome changes.** Make the composer overlay the dock row (absolute, same height) instead of replacing it, and keep the stage size independent of panel/dock state; re-engrave only on rotation. Then the composer can rise on a `layout` spring and the tools it replaces leave with `AnimatePresence`. Effort 2–3 h. Score (and Practice when its dock changes). Mechanics: `AnimatePresence`, layout spring.
3. **Side panels as sprung sheets.** Information box, Markings, History: `motion.aside` sliding from the right (spring 320/30) with a scrim that swallows the dismissing tap, swipe-right to dismiss, `AnimatePresence` exit; in portrait a half-height bottom sheet with a handle; at ≥1100/1360 the docked column reflows the covers/stage with `LayoutGroup`. Effort 3–4 h. Library, Score, Practice. Mechanics: `AnimatePresence`, spring layout, `LayoutGroup`.
4. **Page turn that follows the finger.** Keep the current, previous and next spread mounted in a horizontal track translated by `-spread * width`; drive `x` from the pointer during the swipe; on release spring (320/20/0.8) to the nearest spread by velocity; turn buttons animate the same `x`. Effort 4–6 h (OSMD page divs already exist; the work is the track and the geometry offset). Score, Practice. Mechanics: spring layout.
5. **Scan reorder with `LayoutGroup`/`layoutId`.** Each tile `layoutId={page.id}`; the preview order is already computed (`Scan.tsx:150-155`), so siblings will physically move aside with a spring and the drop snaps into the bracket slot. Add `touch-action: pan-y` and a 350 ms press-to-lift (scale 1.04 + shadow) so the grid scrolls. Effort 3 h. Scan. Mechanics: `LayoutGroup`, `layoutId`, spring layout.
6. **Fix the first engrave of a single part.** Not motion, but the player's landing view is blank or has no page controls until a second render; nothing in 2–5 looks responsive on top of it. Effort 2–4 h investigating `applyInstruments` ordering in `ScoreStage.tsx:120-145`. Score, Practice.
7. **Part switch and skeleton crossfades.** Keep the old SVG visible at 0.4 opacity under the skeleton while a part re-renders, then crossfade the new engraving in over 200 ms; same for skeleton → first render and for rotation. Effort 1.5 h. Score, Practice. Mechanics: `AnimatePresence`.
8. **Practice cursor, brackets and playhead glide.** Animate `.o-cursor` `left` with a one-beat linear tween (duration `60000/tempo` ms) and the loop brackets/ruler bracket with a spring when the loop changes; the tempo readout ticks (digits slide 8 px) on each step. Effort 2 h. Practice. Mechanics: spring layout on bracket positions.
9. **Popovers and cards anchored to their source.** Pin popover, trouble-spot card, display sheet: scale 0.96→1 + fade over 180 ms from the tapped element, exit in 120 ms; cover selection lifts on a spring and the information box header shares a `layoutId` with the cover title. Effort 2 h. Score, Practice, Library. Mechanics: `AnimatePresence`, `layoutId`.
10. **PWA shell.** `viewport-fit=cover` + `interactive-widget=resizes-content`, real icons (192/512/maskable + `apple-touch-icon`), `apple-mobile-web-app-capable`, `black-translucent` status bar with the header padded by `env(safe-area-inset-top)`, dock padded by the bottom inset, launch background from `--ground`, and a `visualViewport` listener that lifts the composer above the keyboard. Effort 1–2 h. Shell. No PinList mechanic.
